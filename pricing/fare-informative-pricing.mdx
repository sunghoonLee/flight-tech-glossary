PNR 없이 특정 운임을 **확정 조회**하고 `uniqueOfferReference`를 발급받는 API 용어집입니다.
FBA(Fare Basis Assignment) 옵션을 사용한 운임 기저 지정 가격 조회도 이 API를 통해 수행합니다.

<Info title="WBS Integration Flow Step 4 / Step 16">
이 API는 [WBS Integration Flow](/amadeus-wbs-integration-flow)의 **가격 조회 및 규정 확인 단계 Step 4** 및 **후속 처리 단계 Step 16 (FBA)**에 해당합니다.
</Info>
---

## 1. 개요

### Fare_InformativePricingWithoutPNR

Amadeus GDS가 제공하는 **PNR 없이 여정의 운임을 확정 가격 조회**하는 API. 항공사, 서비스 공급자 및 거래 파트너가 발권 목적으로 여정의 가격을 요청할 수 있다. 응답으로 `uniqueOfferReference`를 발급받아 후속 발권/규정 조회에 활용한다.

```
[Query: 가격 조회 요청]
  승객 정보, 여정(구간별 항공편), Pricing Option
       │
       ▼
  Amadeus Fare Engine
       │
       ▼
[Reply: 가격 조회 결과]
  mainGroup
  ├─ generalIndicators: SITI/SOTO 등 Pricing Indicator
  ├─ pricingGroupLevelGroup × N (Fare Group별)
  │   ├─ numberOfPax: 해당 그룹 승객 수
  │   ├─ fareInfoGroup: 운임 상세
  │   │   ├─ emptySegment: PTC 정보
  │   │   ├─ pricingIndicators: Ticket Designator, NVA/NVB
  │   │   ├─ fareAmount: 운임 금액
  │   │   ├─ textData: Fare Calculation Line
  │   │   └─ offerReferences: uniqueOfferReference
  │   ├─ surchargesGroup: 세금/패널티/PFC
  │   ├─ corporateGroup: Corporate Fare 정보
  │   ├─ negoFareGroup: Negotiated Fare 정보
  │   └─ segmentLevelGroup × N (구간별)
  │       ├─ segmentInformation: 날짜/항공사/구간
  │       ├─ additionalInformation: Ticket Designator, NVA/NVB
  │       ├─ fareBasis: Fare Basis, Transportation Class
  │       ├─ cabinGroup: 캐빈/클래스 정보
  │       ├─ baggageAllowance: 수하물 허용량
  │       └─ fareComponentDetailsGroup: Fare Component 상세
  ├─ carrierFeeGroup: OB/OC Fee 내역
  └─ fareComponentDetailsGroup: Fare Component/Bound 상세
```

### Query / Reply 구조

| 구분 | 메시지 | 설명 |
|------|--------|------|
| **Query** | `Fare_InformativePricingWithoutPNR 18.1.1A` | 여정 + 승객 + Pricing Option을 포함한 가격 조회 요청 |
| **Reply** | `Fare_InformativePricingWithoutPNRReply 18.1.1A` | 운임 확정 결과 + Offer Reference 반환 |

| 항목 | 내용 |
|------|------|
| API 명 | `Fare_InformativePricingWithoutPNR` |
| 플로우 단계 | Step 4 -- 가격 조회 및 규정 확인 / Step 16 -- FBA 옵션 |
| 목적 | 운임 확정 조회 + Offer ID 발급, FBA 옵션으로 특정 Fare Basis 지정 가격 산출 |
| 이전 단계 | [Fare_InformativeBestPricingWithoutPNR](/pricing/fare-informative-best-pricing) |
| 다음 단계 | [Fare_CheckRules](/pricing/fare-check-rules) |

## 2. Query 주요 구조 (가격 조회 요청)

### passengersGroup

**승객 정보**를 정의하는 구조. 최대 198개 그룹까지 지정 가능.

## 7. offerReferences 및 uniqueOfferReference

```
offerReferences
├─ offerIdentifier
│   ├─ reference     : 참조 번호 (an..6)
│   ├─ offerId       : Offer 식별자 (an..35)
│   └─ uniqueOfferReference : 고유 Offer 참조 (an..60)  ★ 핵심
└─ references        : 승객/구간 Tattoo 참조 (최대 99)
    ├─ type           : 참조 한정자 (Passenger/Segment)
    └─ value          : 참조 번호
```

**uniqueOfferReference**는 이 API의 핵심 출력값으로, 후속 단계인 `Fare_CheckRules`, `Air_SellFromRecommendation` 등에서 해당 운임을 식별하는 데 사용한다. WBS 플로우에서 Step 4에서 발급되어 이후 단계로 전달된다.

## 17. FBA (Fare Basis Assignment) 사용법

FBA 옵션은 **특정 Fare Basis를 강제 지정**하여 가격을 조회할 때 사용한다. WBS 플로우의 **Step 16**에 해당한다.

```
FBA 조회 흐름:

1. Fare_InformativeBestPricingWithoutPNR (Step 3)
   → 최저가 검색, 가능한 Fare Basis 목록 확인

2. Fare_InformativePricingWithoutPNR + FBA (Step 16)
   → pricingOptionGroup에 FBA 키 지정
   → optionDetail.attributeType = Fare Basis Code
   → 특정 Fare Basis로 가격 확정

3. Fare_CheckRules (Step 4 연속)
   → uniqueOfferReference로 규정 조회
```

### FBA vs FBL 차이

| 옵션 | 설명 |
|------|------|
| **FBA** | Fare BAsis simple override -- 시스템이 해당 Fare Basis를 **우선** 사용하되, 불가능하면 대체 운임 적용 |
| **FBL** | Fare Basis force override -- 해당 Fare Basis를 **강제** 적용. 불가능하면 오류 반환 |

---

## 18. RLO (Return Lowest possible fare)

`RLO` 옵션을 지정하면 시스템이 입력된 여정에 대해 **가능한 최저 운임**을 반환한다. `RLI`(Return List of fare)와 함께 사용하면 적용 가능한 운임 목록도 함께 반환받을 수 있다.

```
pricingOptionGroup:
  pricingOptionKey = "RLO"
  → 최저 가능 운임으로 가격 산출
```
